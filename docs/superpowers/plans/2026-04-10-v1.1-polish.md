# v1.1 Polish — Gaps, Issues & Bugs

Identified during subagent-driven execution of the 9 v1.1 plans. Ordered by severity.

---

## Critical / High Priority

### 1. Divergent .claudeignore ignore logic (reindex.js vs cold-start.js)
**Source:** reindex-script code review  
**Issue:** `reindex.js::matchesIgnore` and `cold-start.js::shouldExclude` implement different semantics for glob-with-slash patterns (e.g. `foo/*.js`). `reindex.js` converts these to a proper regex and matches; `cold-start.js` treats them as path-anchored prefixes and misses them. A re-indexed file-map can disagree with a live session's cold-start map.  
**Fix:** Extract `readClaudeIgnore`, `matchesIgnore`/`shouldExclude`, and the file walker into `hooks/lib/walker.js` and import from both callers.

### 2. Silent budget reset in reindex (--budget not preserved)
**Source:** reindex-script code review  
**Issue:** Running `node hooks/reindex.js` (no `--budget` flag) after a previous `--budget 20` run silently resets `token_budget_pct` to 35 with no warning. All accumulated custom budget preference is lost.  
**Fix:** When `budgetPct` is the default, read the existing file-map first and preserve `config.token_budget_pct` if set, or emit a stderr warning that the budget is being reset.

### 3. `**` glob patterns silently fail in .claudeignore
**Source:** auto-cold-start code review  
**Issue:** `.claudeignore` entries like `**/*.log` or `**/dist/` are treated as path-anchored prefixes (because they contain `/`), so they never match. Users copying from `.gitignore` will silently get unexpected inclusions. Affects both `cold-start.js` and `reindex.js`.  
**Fix:** Extend `matchGlobPattern` to replace `**` with `[\s\S]*` and route these to a full-path match, OR log a warning to stderr when `**` is detected in a pattern.

## Important / Medium Priority

### 4. session-buffer.json cleanup not asserted in empty-buffer flush test
**Source:** empty-buffer-test code review  
**Issue:** Test 2 (`flush with empty accesses does not modify existing file-map.json`) does not assert that `session-buffer.json` was cleared after flush. The early-return path does call `clearSessionBuffer`, but a regression dropping that call would go undetected.  
**Fix:** Add `assert.strictEqual(readSessionBuffer(stateDir), null, 'session buffer should be cleared')` at the end of test 2.

### 5. settings-parse-error test doesn't assert warning was emitted
**Source:** settings-parse-error code review  
**Issue:** `tests/state.test.js` test 10 verifies the graceful global fallback but does not assert that `process.stderr.write` was actually called with the warning. A future refactor dropping the warning would silently pass.  
**Fix:** Intercept `process.stderr.write` before calling `detectStateDir`, restore after, and assert the captured output includes `[tokimizer] Warning`.

### 6. Symlinked directories not walked on Windows
**Source:** auto-cold-start code review  
**Issue:** On Windows, junction points (`isDirectory()` returns `false`, `isSymbolicLink()` returns `true`) are silently skipped by `walkDir`. Projects with symlinked `vendor/` or `packages/` directories get incomplete cold-start maps.  
**Fix:** Add `|| (entry.isSymbolicLink() && fs.statSync(abs).isDirectory())` to the directory branch in `walkDir`, or document the limitation in code comments.

### 7. Missing cwd existence validation in reindex CLI
**Source:** reindex-script code review  
**Issue:** `node hooks/reindex.js --cwd /nonexistent` produces `[Tokimizer] Indexed 0 files` with no error, because `walkFiles` silently catches the `readdirSync` failure.  
**Fix:** Add `if (!fs.existsSync(cwd) || !fs.statSync(cwd).isDirectory()) { process.stderr.write('[Tokimizer] Error: cwd does not exist: ' + cwd + '\n'); process.exit(1); }` in the CLI block.

### 8. `buildColdStartFileMap` is async in name only
**Source:** auto-cold-start code review  
**Issue:** The function is declared `async` and returns a `Promise`, but all internal I/O is synchronous (`readdirSync`, `statSync`). On large codebases this blocks the event loop for ~600 ms during session-start. The `async` signature creates a false expectation of non-blocking behaviour.  
**Fix:** Either convert to truly async I/O (using `fs.promises`), or change the signature to sync and update the caller in `session-start.js`. Document the choice.

## Minor / Low Priority

### 9. `process.stdout.write` side effect inside exported `reindex()` function
**Source:** reindex-script code review  
**Issue:** `reindex(cwd, budgetPct)` always prints the summary to stdout, which pollutes output when called programmatically. The summary is already returned as a string.  
**Fix:** Move `process.stdout.write(summary + '\n')` into the `require.main === module` CLI block only.

### 10. Local copy of `normalizePath` in tests is a maintenance liability
**Source:** windows-path-fix code review  
**Issue:** `tests/track-access.test.js` defines its own copy of `normalizePath` mirroring the implementation. If the implementation changes, the test copy will silently drift.  
**Fix:** Export `normalizePath` from `hooks/track-access.js` (or move to `hooks/lib/`) and `require` it directly in the test.

### 11. `last_updated` field absent from `buildColdStartFileMap` output
**Source:** reindex-script code review  
**Issue:** `reindex.js` sets `last_updated: now` in the file-map; `cold-start.js` does not. Any consumer checking `last_updated` behaves differently depending on whether the map came from cold-start or reindex.  
**Fix:** Add `last_updated: new Date().toISOString()` to the returned object in `buildColdStartFileMap`.

### 12. `.claudeignore` itself included in file map
**Source:** auto-cold-start code review  
**Issue:** The cold-start walker includes `.claudeignore` as a tracked project file, which has essentially zero value for context loading.  
**Fix:** Add `.claudeignore` to `HARD_EXCLUDES` in `cold-start.js` (and optionally `reindex.js`).

### 13. No test for zero-file project in reindex
**Source:** reindex-script code review  
**Issue:** `reindex` on an empty directory is untested. Should produce valid file-map with `files: {}` and `project_total_tokens: 0`.  
**Fix:** Add test `'reindex on empty project produces valid empty file-map'`.

### 14. `results.concat()` in `walkDir` creates intermediate arrays
**Source:** auto-cold-start code review  
**Issue:** Recursive `results.concat(walkDir(...))` allocates a new array at every directory level. At large scale (50k+ files) this creates GC pressure.  
**Fix:** Pass an accumulator array by reference, or use a generator (`yield*`) as `reindex.js::walkFiles` already does. Prefer the generator pattern for consistency.

### 15. mtime assertion reliability on Windows (2 test files)
**Source:** empty-buffer-test and hook-tests code reviews  
**Issue:** `flush-scores.test.js` and `session-end.test.js` both use `mtimeMs` comparison to assert files were not rewritten. On Windows with NTFS and fast test runs, millisecond resolution can be identical for two writes that happen within the same clock tick.  
**Mitigation already in place:** Both tests have secondary content assertions (`last_updated`, `access_count`) that are the true safety net. The mtime check is belt-and-suspenders.  
**Fix if flaky:** Replace mtime check with byte-level content comparison (`JSON.stringify(readFileMap(...))` === original serialization).
